Developing smart contracts on **Zilliqa 2.0** has never been easier, thanks to its full **EVM compatibility**.  
If you’re building or testing contracts using **Remix IDE**, there’s one critical detail you must know:

👉 **Zilliqa 2.0 runs the “Cancun” EVM fork — set Remix’s EVM version to “cancun”**.

Recent Solidity compiler versions default to EVM forks newer than Cancun, which can cause deployment or execution errors on Zilliqa’s EVM runtime.  
This guide walks you through setting up Remix IDE for Zilliqa, deploying your first contract, and understanding why the **EVM version** setting matters.

---

## ⚙️ Why Use Remix with Zilliqa?

Remix IDE is one of the most accessible tools for smart-contract developers.  
With Zilliqa 2.0’s EVM support, you can now:

- Compile and deploy **Solidity** contracts directly from your browser  
- Interact with **Zilliqa testnet or mainnet RPC endpoints**  
- Debug and test transactions before publishing  

It’s perfect for testing Zilliqa smart contracts quickly without installing local developer frameworks.

---

## 🧩 The Key Requirement — Set the EVM Version to “cancun”

Zilliqa 2.0’s EVM runtime runs the **Cancun** fork (activated in February 2026), so `PUSH0`, `TSTORE`/`TLOAD` and `MCOPY` all work. Blob transactions and Prague features (such as EIP-7702) do **not**.  
If you compile for an EVM version newer than Cancun — which recent Solidity compiler versions use by default — you may encounter errors such as:

- “Invalid opcode”  
- Deployment failures or gas miscalculations  

To ensure compatibility, set the **EVM version to cancun** in Remix before compiling.

## 🧰 Prerequisites

Before you start, you’ll need:

- A **Zilliqa wallet** (e.g., ZilPay or MetaMask configured for Zilliqa EVM)  
- Access to a **Zilliqa RPC endpoint** (mainnet or testnet)  
- A basic **Solidity contract** to test  
- Browser access to [Remix IDE](https://remix.ethereum.org)

---

## 🧭 Step 1 – Select the Correct EVM Version

1. Open [Remix IDE](https://remix.ethereum.org).  
2. Go to the **Solidity Compiler** tab.  
3. Expand **Advanced Configurations** and set **EVM Version** to **“cancun”**.  
4. Recompile your contract to apply the change.

> **Tip:** The `cancun` option requires Solidity compiler version 0.8.24 or later.

---

## ⚙️ Step 2 – Connect Remix to Zilliqa

1. Go to the **Deploy & Run Transactions** tab in Remix.  
2. Under **Environment**, choose **“Injected Provider – MetaMask”**.  
3. Connect MetaMask to your **Zilliqa RPC endpoint**:

   - **Testnet:** `https://api.testnet.zilliqa.com` (chain ID 33101)  
   - **Mainnet:** `https://api.zilliqa.com` (chain ID 32769)  

4. Confirm your wallet connection.

---

## 💻 Step 3 – Write or Import a Contract

Example contract (`HelloZilliqa.sol`):

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract HelloZilliqa {
    string public message = "Hello from Zilliqa EVM!";

    function setMessage(string calldata newMessage) external {
        message = newMessage;
    }
}
```

Compile it under **Solidity Compiler** with version 0.8.24 or later and **EVM Version: cancun**.

---

## 🚀 Step 4 – Deploy the Contract

1. In Remix, open the **Deploy & Run Transactions** tab.  
2. Select your compiled contract.  
3. Ensure the **Environment** is set to your connected Zilliqa network.  
4. Click **Deploy** and confirm the transaction in MetaMask.

Deployment will appear in Remix’s **Deployed Contracts** panel once confirmed.

---

## 🔍 Step 5 – Interact with Your Contract

Use Remix’s interface to:

- Call read-only functions (e.g., `message()`)  
- Execute write functions (e.g., `setMessage("Hello World")`)  
- Monitor transactions directly on Zilliqa’s explorer  

Zilliqa’s low-latency EVM ensures quick confirmations for these transactions.
